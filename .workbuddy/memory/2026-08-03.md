## 同步 GitHub Pages（gh-pages 推送）

按 DEPLOY.md 手动部署流程，将 `deploy-wiki/` 产物推送到 GitHub Pages：
1. 临时仓库 `/tmp/_v2_deploy`，复制 `deploy-wiki/*` + `.nojekyll`，commit 到 `gh-pages` 分支
2. `git push -f` 到 `https://github.com/szsyqq/my-second-brain-v2.git` gh-pages
3. 认证：`gh` CLI 已登录 szsyqq（token 在 keyring），remote 用 `x-access-token:<TOKEN>@` 注入
4. **关键坑**：系统代理 `127.0.0.1:55507` 对 `github.com:443` 的 CONNECT 隧道极不稳定，频繁返回 `502 Bad Gateway`，直连超时。需多次重试（本次第 4 次成功）。
5. 验证：`gh api repos/szsyqq/my-second-brain-v2/pages` → `https://szsyqq.github.io/my-second-brain-v2/`，source=gh-pages，commit `eabfd1e` 已上线。

### 部署经验（复用）
- 不要直连（无路由），必须走系统代理；但代理对 github 抖动大，脚本里要加重试循环
- `gh auth token` 可拿 token 注入 remote URL，避免交互式认证
- `GIT_HTTP_VERSION=1` 强制 HTTP/1.1，配合重试可提升成功率
