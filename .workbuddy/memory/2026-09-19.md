# 2026-09-19 工作日志

## 触摸屏滑动「滑不到底」修复（知识库查看器 / 全站静态页通用问题）

### 现象
用户反馈：知识库页面在触摸屏上，**左侧目录栏与右侧正文栏都出现回弹卡住、滑不到最低**。

### 根因
`知识库_template.html` 的 app-shell 布局：
- `body{height:100vh;overflow:hidden;display:flex}` —— `100vh` 在移动端是**大视口**（含浏览器地址栏/工具栏所占区域），比用户真正能看见的高度更高；
- `body` 又是 `overflow:hidden`，文档本身永不滚动 → 左右两个内部滚动面板（`#file-tree` / `#content-area`）的底部被推到可见区之外，**且永远无法滚入视野**（滚到容器底时容器底本身在屏幕外，看起来就是"回弹卡住"）；
- 另缺 `overscroll-behavior` → 回弹向上串链，加重"卡住"感。

### 修复（模板 `知识库_template.html`，共 8 处）
1. `body` 高度改为 `height:100vh; height:var(--app-h,100vh)`，并加 `@supports(height:100dvh){body{height:var(--app-h,100dvh)}}` 作为无 JS 的现代浏览器兜底（`var()` 回退值必须用 `100vh` 这种恒合法值，否则 `var()` 失效会让 height 变成 `auto`）。
2. 新增 JS：把**真实可视高度**写入 `--app-h`。源用 `visualViewport.height`，但**必须判 `scale===1`**（捏合缩放时否则整个壳会随缩放缩水）；回退 `innerHeight`；加变化量 guard 避免每个 scroll 事件都触发重排；监听 `resize`/`orientationchange`（旋转后 iOS 会连续几帧报旧尺寸，故 120ms/400ms 再测一次）/`visualViewport` 的 resize+scroll。
3. 移动端 `#sidebar`（`position:fixed`）与 `#inbox-drawer`（`position:fixed`）的 `height:100%` → `height:var(--app-h,100%)`（固定定位的高度按视口解析，同中招）。
4. 四个滚动容器（`#file-tree` / `#content-area` / `#update-drawer-body` / `#inbox-drawer-body`）加 `overscroll-behavior:contain`（阻断回弹串链）+ `min-height:0`（flex 列子项正确收缩）+ `-webkit-overflow-scrolling:touch`。
5. 移动端 `#content-area` 底距补 `env(safe-area-inset-bottom)`。

### 验证（关键：真实布局引擎 + A/B 对照）
本机只有 `puppeteer-core`（无自带浏览器），用**系统 Chrome** 作 `executablePath`。headless 里 `innerHeight === visualViewport.height`，无法自然复现"工具栏吃掉 100vh"的条件 —— 故把模拟视口当作**大视口**、以 `视口−90px` 当作**用户可见高度**，三种规则对**同一可见基准**测量：

| 场景 | body 高度 | 面板底部 | 折叠线下被藏高度 |
|---|---|---|---|
| A 现状（`--app-h` 驱动） | 754 | 754 | **0** ✅ |
| B 旧规则（`body:100vh`） | 844 | 844 | **+90** ❌（复现 bug） |
| C 无 JS 兜底（`100vh`） | 844 | 844 | +90（已知，等同旧行为） |

侧栏（移动端固定定位）同测：高度 754、底部 754、被藏 0、树内容 5907px 可滚到末端 ✅。
另单独确认页面**自身 JS** 在加载时设 `--app-h=844`、视口改为 700 后自动跟随为 700（非手动赋值假象），`pageErrors: []`。

## 第二轮（当日续）：「更新历史」抽屉重构为统一双 tab 框架

### 用户诉求
「每个页面上的更新历史有逻辑错误，应该分为的两个 tag 是本页面的更新历史和全部的更新历史……目前有一个不存在功能的策略 tag，应该被优化掉。同时全部处理下所有页面的这个逻辑，检查是否为统一框架。」

### 审计发现（原实现有 3 套并行语义 + 6 处逻辑错误）
1. **两套并行状态**：tag 组用 `currentUpdateTab`（all/strategy），页面视图另用 `updateDrawerMode`（global/page）——同一个抽屉两套状态机。
2. **「策略」tag 无实际功能**：`getStrategySlugs()` 用 `slug.startsWith('topics/02_')` 过滤，命中 19/22 条记录（几乎不具区分度），且与用户想要的「本页」语义无关 → 删除。
3. **页面模式下 tag 失效**：`switchUpdateTab()` 走 `renderUpdateRecords()`，而后者在 `updateDrawerMode==='page'` 时仍渲染页面过滤结果 → 点 tag 无反应。
4. **伪配对**：`renderPageHistory()` 用索引算术 `hist.length - hi === pageUpdates.length - ui` 把更新记录与快照"配对"——但快照由 `bundle_wiki.py` 归档时**只存 version + content，没有时间戳**，二者根本无法配对 → 改为两节并列（本页历次更新记录 / 本页内容快照）。
5. **计数误导**：标题用 `(pageUpdates.length || hist.length)`，两者都存在时只显示前者。
6. **记录标题点击错跳**：本应打开该次更新详情，却调用 `switchToGlobalHistory()` 跳到全部列表。
7. **入口覆盖不全**：`insertPageRecButton()` 依赖 `#content-area h1`，而 12 个页面（`sources/*` 等）正文无 H1 → 永远没有入口按钮。
8. **导航不跟随**：抽屉开着时切页面，内容仍是上一页的（`openPage` 未通知抽屉）。
9. **首页卡片名不副实**：「查看完整更新历史 →」实际跳的是最新一条记录页。
10. **第三/第四套死实现**：`openHistoryPanel`/`renderHistoryList`/`closeHistoryPanel` + `.hist-btn`/`.history-item` + `.phs-*`/`.page-hist-*` 样式全部无引用。

### 修复（全部在 `知识库_template.html`）
- 单一状态源 `var updTab = 'all' | 'page'`，`renderUpdateRecords()` 为唯一出口并按 tab 分派；新增 `syncUpdateTabs()`（active + disabled + 计数徽标）、`switchUpdateTab()`（无页面时拒绝并提示）、`refreshUpdateDrawer()`。
- 两个常驻 tag：「本页更新历史 (n)」「全部更新历史 (n)」；首页/无页面时本页 tag 置灰。
- 本页 tab = 「📝 本页历次更新记录」（level + 记录标题可点开该次更新 + 日期 + 类别 + 本页改动描述）+ 「📜 本页内容快照」（查看 / 对比当前），**不再做索引配对**。
- 入口收敛为三处且语义一致：侧栏「更新历史」→ 全部；页面标题旁按钮 → 本页（无 H1 时兜底到 `#content-header`）；首页卡片 → 全部。
- **取消「打开页面自动弹出抽屉」**（`info.update_severity` 触发）——它导致用户点按钮反而"关闭抽屉"，两个入口语义不一致。
- 删除「策略」tag 及 `getStrategySlugs`/`getFilteredStrategyRecords`、`updateDrawerMode`/`getFilteredRecords`/`renderPageHistory`/`switchToGlobalHistory`，以及上表第 10 项死代码与死样式。
- 抽屉标题加固定 id `update-drawer-heading` / `update-drawer-subheading`（可断言、可维护）。
- VERSION 2.0.7 → **2.0.8**，`应用更新记录.md` 补一行（UI 重构属"次版本"）。

### 踩坑：大文件 JS 语法错误定位
改模板时误留一个重复的 `function renderUpdateRecords() {` 头 → `node --check` 只报 `SyntaxError: Unexpected end of input`（位置在 EOF，无用）。有效三招：
1. **acorn 拿精确位置**：`NODE_PATH=<node_modules> node -e "acorn.parse(fs.readFileSync(f),{ecmaVersion:2022})"`，报错仍指向 EOF，但配合下列第 2 招可定位函数名；
2. **补括号试探**：给源码末尾追加 n 个 `}` 再 parse，n=1 通过 → 说明只缺 1 个闭合，再用 acorn 遍历 AST 找 `end` 贴近 EOF 的节点 → 直接得到"未闭合函数名 + 起始行"；
3. **用构建产物作语法基准**：`知识库.html` 的脚本块可 `node --check` 通过（无 PLACEHOLDER），与模板脚本块 diff 即可把"我引入的改动"从历史差异中隔离出来。
