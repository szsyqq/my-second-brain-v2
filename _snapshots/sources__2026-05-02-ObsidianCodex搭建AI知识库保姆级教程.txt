

# 我用Obsidian + Codex 搭了一个会持续进化的AI知识库，保姆级教程来了

## 核心观点

1. **LLM Wiki 不是 RAG**：RAG 是"存进去 → 切片检索 → 拼答案"，LLM Wiki 是"资料进 raw → Agent 编译知识 → wiki 沉淀 → 优先在 wiki 层回答"。差别在于知识是否越用越好用。

2. **最小闭环先行**：不要一上来就设计复杂结构。先跑通 raw/→ wiki/ 两层目录 + AGENTS.md 规则文件 + 一篇资料 + 一次 ingest 的链路。30 分钟内验证比花 2 小时画 schema 更重要。

3. **知识库的复利来自于"回写"**：不仅是 ingest 新资料，还要把高质量问答回写到 wiki。一旦开始这样做，知识库就从"只吸收新资料"升级为"也吸收新问题"。

4. **三个翻车点**：raw/wiki 混放、只让 Agent 做摘要不更新知识网络、只 ingest 不查询也不回写。这三者分别对应结构混乱、知识孤岛、无复利积累。

5. **Codex/Agent 的核心价值**在于它能直接读写本地文件，让知识库从"手动维护的笔记系统"变成"Agent 持续构建的 wiki 系统"。

## 原文精彩摘录

> 大部分人的做法：收藏一篇文章，写一段摘要，扔进文件夹，下次要用了再翻出来。LLM Wiki 的做法：资料进来 → Agent 帮你整理 → 更新概念页、主题页、索引页 → 下次提问时，Agent 优先站在已经整理过的 wiki 层回答。区别在哪？前者是存资料，后者是编译知识。

> 先跑通，再优化。一上来就设计超级复杂的结构几乎总是低效的，因为你根本不知道自己的 ingest 动作会不会稳定发生。
