

# 使用说明

> 知识库使用指南：介绍 `/sl`、`/gx` 等核心指令的使用方式、工作原理，以及知识库的整体运作流程。

---

## 一、核心理念

这个知识库是一个**第二大脑**，目标是把碎片化的收藏（小红书笔记、微信公众号文章、知乎帖子等）转化为**结构化、可检索、可持续积累**的知识体系。

运作模式：**收藏 → 消化 → 沉淀**，你只需要两个步骤。

---

## 二、日常操作流程

```
┌─────────────────────────────────────────────────┐
│                    日常流程                       │
│                                                   │
│  看到好文章                                       │
│     │                                             │
│     ▼                                             │
│  /sl <URL>        ← 收藏归档到 raw/inbox/         │
│     │                                             │
│     ▼                                             │
│  /gx              ← 批量消化 + 移到 processed     │
│     │                                             │
│     ▼                                             │
│  知识库更新 ✓     ← wiki 页面已生成，可查询/回顾    │
│                                                   │
└─────────────────────────────────────────────────┘
```

| 命令 | 功能 | 输入 | 输出 |
|------|------|------|------|
| `/sl` | **收录**（Save Link） | URL（一个或多个） | 归档到 `raw/inbox/` 对应子目录 |
| `/gx` | **更新**（Generate eXpert） | 无（自动扫描 inbox） | 消化所有待处理素材 → 移到 `raw/processed/` |

## 三、/sl 命令详解

### 作用

将你分享的链接自动分类保存到知识库的 `raw/inbox/` 目录中，等待后续消化。

### 使用方法

直接在对话中输入 `/sl` 后跟一个或多个 URL：

```
/sl https://www.xiaohongshu.com/explore/xxx
/sl https://mp.weixin.qq.com/s/xxx https://zhuanlan.zhihu.com/p/yyy
```

### 自动分类规则

`/sl` 会根据 URL 特征自动识别来源并分类到对应子目录：

| URL 特征                            | 来源        | 归档目录                     |
| --------------------------------- | --------- | ------------------------ |
| `xiaohongshu.com` / `xhslink.com` | 小红书       | `raw/inbox/xiaohongshu/` |
| `zhihu.com`                       | 知乎        | `raw/inbox/zhihu/`       |
| `mp.weixin.qq.com`                | 微信公众号     | `raw/inbox/wechat/`      |
| `x.com` / `twitter.com`           | X/Twitter | `raw/inbox/tweets/`      |
| 以 `.pdf` 结尾                       | PDF       | `raw/inbox/pdfs/`        |
| 普通网页（以上都不匹配）                      | 网页文章      | `raw/inbox/articles/`    |
| 纯文本（无 URL）                        | 笔记        | `raw/inbox/notes/`       |

### 工作原理

1. **解析来源**：根据 URL 域名判定来源类型
2. **抓取内容**：尝试抓取页面标题和正文（小红书等 JS 渲染站点可能抓取失败，不影响归档）
3. **AI 自动打标签**：基于内容自动分配 1-4 个中文标签
4. **去重检查**：通过 SHA256 哈希避免重复归档
5. **生成文件**：在 `raw/inbox/` 对应子目录创建 Markdown 文件
6. **回报结果**：告知归档了几个链接、分类结果、有无失败

### 归档后文件示例

`/sl` 归档后，`raw/inbox/xiaohongshu/` 下会生成类似这样的文件：

```
xiaohongshu-2026-07-11-a3f.md
```

文件内含 frontmatter 元数据（标题、URL、来源、标签、摘要）和抓取到的正文。

## 四、/gx 命令详解

### 作用

批量处理 `raw/inbox/` 中所有待消化的素材，通过 AI 将其转化为结构化的 wiki 页面（素材摘要、实体页、主题页），处理完毕后将源文件移至 `raw/processed/`。

### 使用方法

直接在对话中输入 `/gx`（无需参数）：

```
/gx
```

### 工作流程

1. **扫描 inbox**：列出所有待处理文件，按子目录分组统计
2. **确认范围**：展示待处理列表，询问是全部处理还是指定部分
3. **逐个消化**：对每个文件执行完整 ingest 流程：
   - 读取文件内容
   - 根据正文长度自动选择「完整处理」或「简化处理」
   - 生成 `wiki/sources/` 素材摘要页
   - 提取关键概念，创建或更新实体页（`wiki/entities/`）
   - 创建或更新主题页（`wiki/topics/`）
   - 更新 `index.md` 和 `log.md`
   - 评估投资相关性
4. **移动文件**：处理完成后将源文件从 `raw/inbox/` 移至 `raw/processed/`
5. **总结报告**：汇总新增和更新的页面数量、文件移动列表

### 两级处理模式

| 模式 | 触发条件 | 处理内容 |
|------|----------|----------|
| **完整处理** | 素材 > 1000 字 | 生成摘要页 + 创建/更新实体页 + 创建/更新主题页 + 更新索引 + 质量检查 |
| **简化处理** | 素材 ≤ 1000 字 | 生成摘要页 + 提取关键概念 + 更新索引（跳过主题页创建） |

### 消化后的产物

每次 `/gx` 消化会产生三类 wiki 页面：

| 页面类型 | 目录 | 说明 | 示例 |
|----------|------|------|------|
| 素材摘要 | `wiki/sources/` | 每个素材一篇摘要，提取核心观点 | `2026-07-11-HSBCHKpulse内地澳门MO实战.md` |
| 实体页 | `wiki/entities/` | 人物、组织、概念、工具的详细介绍 | `HSBC Pulse信用卡.md` |
| 主题页 | `wiki/topics/` | 围绕某个主题的综合分析（含子文件夹层级） | `旅游/日本旅游.md`、`信用卡.md` |

## 七、其他能力

### 查询知识库

直接在对话中提问，AI 会自动搜索 wiki 页面中的相关内容并综合回答。例如：

- "日本旅游有什么推荐？"
- "HSBC Pulse 信用卡怎么用最划算？"
- "瑞士签证要注意什么？"

### 企业微信集成

通过企业微信转发的文章会自动分类到 `raw/inbox/`，无需手动 `/sl`。

## 八、常见问题

**Q: `/sl` 和 `/gx` 需要按顺序使用吗？**

是的。先用 `/sl` 收藏链接到 inbox，积累一定数量后，用 `/gx` 批量消化。

**Q: 可以一次 `/sl` 多个链接吗？**

可以，一行输入多个 URL 即可。

**Q: `/gx` 会重复处理吗？**

不会。已处理的文件会移至 `raw/processed/`，下次 `/gx` 只处理 inbox 中新增的。

**Q: 什么时候用 `/gx`？**

随时可用。建议 inbox 积累 3-5 篇后运行一次，或者随时想说"更新"时运行。
