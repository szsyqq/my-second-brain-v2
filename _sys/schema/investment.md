## 投资模块定位

本模块是**「内容驱动、三层递进」的投资决策系统**：**宏观定基调 → 行业选方向 → 个券落地**。三层相互关联，更新时联动。

- 核心矛盾：信息**持续流入**（新闻、研报、个券报告、市场速览） vs 决策**离散发生**（买 / 卖 / 加 / 减）。
- 解决方式：每条进来的内容，先按**「四问」**过一遍投资经理的决策视角，判断属于哪一层与多空属性，再归到对应档案按时间累积。
- 完整方法论见 `wiki/topics/02_投资/02-00_投资内容处理手册.md`。

## 概念更正：锚点 = 估值锚点（不是内容分类）

- **锚点（valuation anchor）** 是每个行业 / 个券的「贵贱判断基准」，挂在档案上的**属性**，不是给单条内容贴的标签。
- 锚点类型：① 倍数中枢（PE/PB/PS/EV-EBITDA 中枢）② DCF 内在价值 ③ 基本面驱动（单位变量→利润弹性）④ 可比交易（并购/定增/回购价）。
- **锚点变动触发条件**（`anchor_drivers` 字段）：盈利预期修正 / 无风险利率与风险溢价 / 行业格局与竞争结构 / 同业重定价 / 资本运作（回购/分拆/并购/注资）。
- 处理内容时持续追问：它是在**移动锚点**，还是只在**围绕锚点波动**？

## 宏观层规范（v7.5 交易化重构）

宏观层由两类页面组成，**方法与状态严格分离**：

| 页面 | type | 职责 | 更新频率 |
|------|------|------|----------|
| [[02-10-00_宏观交易手册]] | `manual` | **方法论**：七大框架 + 定位指标 + 「宏观状态→资产动作总表」+ 失效纪律。**不放时效性判断** | 低频（新框架素材进来或框架参数修正时） |
| [[02-10_宏观]] | `hub` | **当前状态**：立场速览 / 仪表盘 / 周期定位 / 大类资产方向 / 信号流 / 决策台账 | 每次宏观素材消化时 |
| `02-10-NN_宏观子题.md` | `topic`（layer: macro） | 宏观子主题（如量化预测范式） | 随素材 |

### 宏观枢纽 frontmatter 规范（可扫描交易字段）

```yaml
---
type: hub
layer: macro
regime: 货币×信用象限判定        # 如 宽货币+紧信用（弱复苏，类滞胀扰动）
risk_appetite: 高/中/低          # 当前风险偏好结论
liquidity: 宽松/中性/收紧        # 流动性状态（一句话补充）
asset_direction: 一句话大类资产方向  # 如 债券超配 · 股票结构性 · 商品能源链偏多
next_catalyst: "下一催化剂(日期)"
review_date: YYYY-MM-DD          # 下次必须重审的日期
confidence: 高/中/低             # 对象限判定的把握
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 宏观枢纽六节结构

0. **宏观立场速览**（≤5 行）：象限判定 + 一句话逻辑 + 当前最大矛盾 + 风险偏好
1. **宏观仪表盘**（五维 ≤8 指标：增长/通胀/货币/信用/海外，含当前状态 + 多空阈值 + 最近更新）
2. **周期定位**：康波 / 库兹涅茨 / 库存周期坐标 + 判定含义（结构市 or 总量市）
3. **大类资产方向**：资产｜方向｜依据｜复核条件 四列表
4. **宏观信号流**（标准化表，沿用信息流六列格式）：**信号判定标准 = 是否改变 象限判定 / 周期定位 / 大类资产方向**（宏观版「锚点移动」）；相左观点必须保留并标注
5. **决策与问责台账**（沿用）+ **宏观→行业传导表**（受益/受损行业 + 日期）

### 宏观内容处理规则

- 宏观素材走四问后，第一步对照 [[02-10-00_宏观交易手册]] 判定：**是否改变象限 / 周期定位 / 资产方向**？
  - 改变 → 属「观点变化」：更新枢纽 frontmatter（`regime` / `risk_appetite` / `asset_direction`）+ 触发**宏观→行业反向联动**（重审受影响行业页 `stance`，更新记录列入观点变化）
  - 不改变 → 记入信号流表，标「围绕现有判断波动」
- **新框架类素材**（首席方法论、分析框架、复盘范式）→ 落到交易手册对应框架节（新增框架 or 修正参数，标日期与来源）；时效性观点仍落枢纽页信号流。
- 枢纽页 `review_date` 到期未更新 = lint 警告项。

## 行业档案（topic）frontmatter 规范

```yaml
---
type: topic
layer: industry
industry: 行业名              # 如 航空航天 / 军事与国防 / 科技TMT半导体
asset_class: 股票/转债/商品/固收/多资产
stance: 超配/标配/低配/回避     # 立场：全库唯一排序真相源，每次 gx 联动更新
cycle_stage: 回升期            # 基本面周期七阶段：下行→出清初/中/末→回升→扩张→筑顶
life_stage: 成长期             # 产业生命周期：导入/成长/成熟/衰退
prosperity: 上升/持平/下降      # 景气度方向（一句话依据）
valuation_percentile: 高/中/低(约N%)  # 估值分位：相对自身历史、相对市场（粗颗粒可）
crowding: 高/中/低             # 拥挤度：落入景气-拥挤四象限哪一格
next_catalyst: "下一催化剂(日期)"  # 枢纽页直接抽取；无日期写"待定"
valuation_anchor: 一句话估值锚点   # 倍数中枢 / DCF 内在价值 / 基本面驱动
anchor_drivers: [导致锚点变动的因素关键词]
review_date: YYYY-MM-DD       # 下次必须重审的日期
confidence: 高/中/低           # 对锚点的把握
macro_link: 关联宏观页（可选）
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [关联素材]
---
```

行业档案结构（**「选赛道 → 定状态 → 做交易」十节**，详见 [[模板_行业档案]]）：

0. **立场速览**（≤5 行）：立场 + 一句话逻辑 + 当前最大矛盾
1. **监测仪表盘**（≤5 指标 + 当前值 + 多空阈值 + 频率 + 最近更新）：盯盘清单
2. **周期坐标**：生命周期（导入/成长/成熟/衰退）+ 基本面七阶段 + 资本周期信号（供给侧前瞻）+ 改判条件
3. **供需与景气**（量-价-库存）：需求端 / 供给端 / 库存与价格 / 景气度方向
4. **产业链与利润池**：链条图 + 利润集中与迁移 + 景气传导（领先滞后）+ 竞争格局一行表（CRn/龙头/壁垒）
5. **估值与拥挤度**：估值锚点（沿用）+ 估值分位 + 拥挤度（落四象限）
6. **多空因素**（三列表，沿用）+ **催化剂日历**（带日期带动作）
7. **情景与交易计划**（playbook）：基准/上行/下行三情景的触发条件、动作、涉及个券
8. **信息流**（标准化表，沿用）+ **决策与问责台账**（沿用）
9. **关联个券**（增加「行业β传导」列：行业观点变化如何映射到该个券）
10. **债券视角**（可选节，有存续债/产业债的行业启用）：行业利差 / 融资环境 / 尾部风险 / 景气联动准入标准

> 估值分位、拥挤度允许定性粗填（高/中/低 + 约数），杜绝「字段空着等精确数据」。

枢纽页 `02-20_行业.md` 改为「比较仪表盘 + 胜率×赔率四象限」，行字段取自各档案 frontmatter（stance/cycle_stage/prosperity/valuation_percentile/crowding/next_catalyst），`/gx` 收尾步骤须同步刷新。

### 多空因素写法（每个行业 / 个券必填，三列表）

利好、利空各一张表，三列固定：

```
**利好**
| 利好因素 | 具体逻辑 & 来源 | 强化↑ / 消退↓ / 持平→ |
|----------|-----------------|------------------------|
| A. 简述 | 为什么成立+证据（来源：[[ ]]） | 当前趋势 |

**利空** —— 同上结构
```

- 第一列：因素简述（A/B/C）；第二列：具体逻辑 + 证据 + `[[来源]]`；第三列：该因素**当前趋势**（强化/消退/持平，取代旧的 ✓/○/✗ 是否已发生标记）。
- 收口：**如何驱动下一步投资**（结论：建/加/减/观望 · 触发条件 · 复盘点），可并入决策区或单列。

## 个券档案（security）frontmatter 规范

```yaml
---
type: security
layer: security
security_name: 公司简称          # 如 Meta Platforms
ticker: 交易所.代码              # 如 USMETA / 600118.SH / HK0700
industry_tags: [行业A, 行业B]    # 所属行业标签，用于跨层关联
asset_class: 股票/转债/基金/ETF
related_industry: [[02-2X_行业名]]  # 关联行业页
valuation_anchor: 一句话估值锚点
anchor_drivers: [导致锚点变动的因素关键词]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [关联素材]
---
```

个券档案结构（**投资经理尽调八段**，见 [[模板_个券档案]]）：
1. **公司概览**：主营业务一句话 + 行业地位（龙头/份额）。**业务占比不在这里，见第 2 节**。
2. **业务构成（独立小节）**：表格讲清收入/利润由哪些板块构成、各自占比——利润来源是否集中、风险在哪的底数。
3. **关键财务指标**：三要素表 = 现值 / 对比基准（同业·历史·一致预期）/ 为何看它。删「关键判断标准」等不指向决策的字段。
4. **核心逻辑**（不能简单）：先写一句**总述**，再展开：
   - **4.1 所属行业**（可跨多行业，钱从哪来、往哪走）
   - **4.2 投资逻辑主线**（一句话主线 + 凭什么持续赚钱、为何现在值得关注）
   - **4.3 护城河**（专门讲护城河：每条是什么、当前是否稳固，A/B/C 标 ✓/○/✗）
   - **4.4 竞争与替代**（对手 / 替代进度 / 自身身位）
   - **4.5 关键关注 / 未来关注重点**：把「每条护城河是否稳定」转成**前瞻盯防清单**——列几个点，每个点写清「为什么盯、盯什么信号/阈值」；是驱动下一步跟踪与决策的输入
5. **估值锚点**：类型 / 当前值与安全边际 / 什么会移动锚点。
6. **多空因素**：利好、利空两张三列表（见上）。
7. **信息流（标准化表）**：字段成列，信息内容要「具体概括」。
8. **决策区**：决策与问责台账（见下）。
- 末尾顺序：**待探索** → **关联行业（置底，向上链接所属行业页）**。

> 占比/财务等数据若来自公开常识而非本库来源，标注「(约/待核实)」，不得把估算当精确源数据。

## 信息流表格化（v7.1）

> 定性/催化性质/信号判定是**标准化字段**，应表格化沉淀（成列），不再每条写成散文段落。

| 日期 | 信息内容（具体概括） | 定性 | 催化性质 | 信号判定 | 来源 |
|------|----------------------|------|----------|----------|------|
| … | 写清事件/数字，不只写标签 | 利好/利空/中性 | 突发/渐进/验证证伪 | 决策信号/噪音/过时 | [[来源]] |

- 字段取值：定性=利好/利空/中性（**原「锚点」作内容分类已废弃**）；催化性质=突发/渐进/验证证伪（原「爆点」）；信号判定=决策信号/噪音/过时（尤其是否移动锚点）。
- 「机会」与「观点对齐（相左必须保留）」在四问思考时仍要过，但落表时可并入信息内容或转入决策区，避免信息流冗长。

## 决策区的作用（v7.1）

> 决策区 = **决策与问责台账**，与信息流严格区分：信息流记「外部进来的信息与判断」，决策区只记「我基于分析做出的实际动作 + 复盘」。

| 日期 | 决策（建/加/减/观望） | 依据（触发条目） | 状态 | 复盘结论 |
|------|------------------------|------------------|------|----------|

- 作用：检验判断对错、约束追涨杀跌、留可回看的决策轨迹。长期为空说明无实际决策，可折叠，但不得用信息记录填充。

## 四问处理法（单条内容标准流程）

每进一条内容，先问自己：

1. **定性（多空 + 催化）**：偏 利好 / 利空 / 中性？催化性质是 突发 / 渐进 / 验证证伪？
2. **信号判定**：决策信号 / 噪音 / 过时？
3. **机会**：带来什么投资机会？（方向 + 资产 + 逻辑链）
4. **观点对齐**：与已有观点 相同 / 相左 / 新维度？

→ 判断属于哪一层与多空属性，归到对应档案；主题不存在就复制模板新建。

## 市场速览（科技日报 / 周报）处理规则

- 科技日报 / 周报 是美股科技、半导体、超大规模云厂 capex、内存周期与前沿模型的**每日 / 每周市场速览**，内含大量**个券报告、目标价、评级与多空判断**。
- 它们**已经可以、也应该被总结**：凡涉具体个券（META / NVDA / AVGO 等）的判断，走四问后**落到对应个券档案**（无则按命名规则新建）；凡涉行业（AI 半导体、内存周期）的判断，落到对应行业档案（无则新建 02-23_科技TMT半导体 等）。
- 来源页（如 `2026-07-13-科技日报-0710`、`2026-07-13-科技周报-0713`）作为「信息流」条目的来源链接保留，方便回溯原始底稿。

## 写作规则

1. 每条内容必答四问，不允许"只摘抄不判断"。
2. **相左观点必须保留**，不人为过滤反面证据。
3. 机会无则明写"暂无直接机会"，不硬凑。
4. 每个观点 / 数据标注来源（`[[来源摘要页]]`）。
5. 每个行业 / 个券档案必须维护「多空因素」与「如何驱动下一步投资」。
6. 每个行业档案必须按十节结构维护，frontmatter 同步填 `stance` / `cycle_stage` / `life_stage` / `prosperity` / `valuation_percentile` / `crowding` / `next_catalyst` / `review_date`；无精确值可定性粗填（高/中/低 + 约数）或标注「（初判，待素材验证）」，不猜测、不空白。
7. 处理内容时标注它**是否移动了估值锚点**。
8. 监测仪表盘硬上限 5 个指标；催化剂必须日历化（带日期与动作）；交易计划必须三情景（基准/上行/下行）。
9. 空缺诚实标注「（待积累）」，不猜测。
10. wikilinks 用实际文件名。
11. 更新行业档案时检查关联个券是否需要联动，并同步刷新 `02-20_行业.md` 比较仪表盘对应行；更新个券时检查行业估值锚点是否受影响。
12. 宏观枢纽必须维护六节结构与 frontmatter 交易字段（`regime` / `risk_appetite` / `asset_direction` / `review_date`）；**方法论进 [[02-10-00_宏观交易手册]]，时效性判断进 [[02-10_宏观]]**，两者不得互相混入；象限/周期/资产方向改变时必须触发宏观→行业反向联动并列入观点变化。
